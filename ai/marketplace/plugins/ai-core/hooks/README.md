# ai-core hooks

| File | What |
|---|---|
| `hooks.json` | Claude Code hooks (Claude loads it by default; plugin.json does not list it) |
| `codex-hooks.json` | Codex hooks (`.codex-plugin/plugin.json` `"hooks": "./hooks/codex-hooks.json"`) |
| `router.py` | one entry point for every event: L1 inject, L2/L3 prompt rules, nudges, miss log |
| `hooklib.py` | shell command parser, the three gates (L4), shared helpers |
| `claude-notify` | owner notification (macOS desktop, Linux webhook through the root helper) |
| `serena-hook` | runs vendor `serena-hooks activate` / `cleanup` when Serena is installed |
| `routing.json`, `L0.md` | generated by `ai/bin/ai-render` (gitignored copies; the router reads `$AI_HOME/ai/build/` first) |

Codex trusts hooks per script hash (`/hooks`). Routing changes edit only `routing.json` (data), so they need no
new trust. A change to `router.py`, `hooklib.py`, `claude-notify` or `serena-hook` needs a new trust in Codex.

Tests: `bash ai/tests/run.sh` (should-fire and should-not-fire stdin samples for every rule).

## Gates

Gates catch honest mistakes. They are not a sandbox against an adversary: an agent that wants to bypass a
gate can (for example, write a script file and run it). Escape hatch for a real exception, owner only:
`sudo ai-gate-skip <gate> <minutes, max 60> <why>` writes the root-owned `/etc/ai/gate-skip`; the router lets
that gate through until the time runs out and logs each skip to `~/.local/state/ai/gates.log`. Agents have no
sudo, so they cannot skip a gate themselves. `AI_GATE_SKIP=...` in a command does nothing any more.

How the command is read: a small shell parser splits the command into stages on `&& || ; | &`, `( )`,
`$( )`, backticks and `<( )`, removes heredoc bodies, skips env assignments and wrappers (`sudo -u x`,
`env A=1`, `timeout 5`, `xargs`, `nohup`, `exec`), and reads `bash -c "..."`, `sh -c`, `eval` one level
deeper. Quoted words are never read as commands, so commit messages and echo text do not trigger a gate.

- audit-before-install: npm, pnpm, yarn, bun, pip (any `pip3.x`, `python3.x -m pip`), `uv add`,
  `uv pip install`, `uv tool install` (also `--from` / `--with` values), `uv run pip` need a PASS in
  `audit.log` within 24 h. A lockfile or `-r` / `-e` install needs a `dir` audit of the project.
  curl or wget into a shell or interpreter, `bash <(curl ...)`, `sh -c "$(curl ...)"` and `npx ...@latest`
  are always blocked. brew, cargo, go, gem, pipx, URL installs and installs it cannot parse ask the owner
  (Codex has no ask: deny with a message).
- secret-scan: `git commit` scans the staged diff; with `git add` earlier in the same command, `commit -a`
  or a commit pathspec it also scans unstaged changes and untracked files. `git push` scans commits not
  on any remote (last 300). gitleaks runs too when installed. Allowlist: only the context7 key, exact
  value, from committed (HEAD) MCP config of this repo or `CONTEXT7_API_KEY` in `~/.config/ai/secrets.env`.
- pr-rules: `gh pr create` and `gh pr edit` with a body need a mermaid block and the author-sessions block.

A gate decision is sent even when the state dir cannot be written; an internal error before a decision
fails open and is logged to `~/.local/state/ai/router-errors.log` (ai-doctor shows it).
The secret scan has a time budget under 20 s (git 5 s and gitleaks 10 s per call). On a timeout it
denies ("scan timed out, nothing was checked"); it never passes unscanned.
State files (`gates.log`, `fired.jsonl`, `misses.jsonl`, ...) are created with mode 0600. Commands in
`gates.log` are redacted with the secret patterns plus any `NAME=value` where NAME looks like a
key, token, secret or password.

## Known limits (accepted, documented; owner: keep it simple)

- The install gate is advisory: `~/.local/state/ai/audit.log` is writable by the same user the agent
  runs as, so an agent could append a fake PASS line. The gate stops honest mistakes, not a hostile
  agent; the owner's review of agent-audit output stays the real control.

- `pip install "foo @ https://..."` and other direct references are audited by name only; a local path
  or archive maps to the project `dir` audit.
- `pnpm add -w foo`: `-w` is a flag in pnpm and an option with a value in npm; per-tool lists may still
  misread rare flag combinations. `npm install \` with a line break is handled; other odd quoting may not be.
- Audit matching: an unpinned install is satisfied by a PASS for any version of that package; the newest
  log line for a package wins (a later PASS hides an older FAIL of another version); a `-` version PASS
  covers all versions.
- `npm update`, `npm exec`, `pnpm dlx` without `@latest`, `pip download` and package managers not listed
  above are not gated.
- Commit: `git commit` with no commits yet and a pathspec scans index + worktree; `--only` semantics are
  approximated. The `-a` flag is read from the parsed arguments, not from message text.
- Push scan reads at most 300 unpushed commits and only HEAD (not other pushed refs).
- A gitleaks error other than a timeout (bad report, crash) is logged and only the builtin patterns count.
- `gh pr create -F file`: a relative path is read from the hook cwd (a `cd` earlier in the command is
  not applied); `--body-file -` (stdin) can only be checked when the heredoc is in the command.
- Codex: file edits by `apply_patch` are not checked by no-em-dash or graph-update (Bash and Claude
  Edit/Write only); re-inject after compaction uses SessionStart source `compact`.
- Builtin secret patterns are a fixed list; new token formats need a new pattern or gitleaks.
